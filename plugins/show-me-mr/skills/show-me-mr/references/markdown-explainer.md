# Markdown explainer

Write `.show-me/mr-{id}/explainer.md`. It is the portable version of the explanation: it renders on GitHub and GitLab (both render Mermaid), it diffs well, and it is the body for `--post`. A reader who never opens the HTML page or the video must still understand the change from this file alone.

## Template

Fill in every `{...}`. Delete any section or view that does not apply. Do not leave empty headings.

````markdown
# {PR/MR title}

[{host} !{n} / #{n}]({url}) · `{base}` ← `{head}` · **+{added} / −{removed}** in {file count} files · {author}

## What this change does
{1 to 3 STE sentences.}

## Why
{1 STE sentence.}

## Read this first
- **Warning:** {data loss, security, or breaking change}
- **Note:** {migration, flag, deliberate omission, surprising decision}

## Review order
1. `{path}`: {what to check, one sentence}
2. ...

## Change outline

{One STE sentence that introduces the view.}

```diff
{level 2 view}
```

{One STE sentence that introduces the next view.}

```mermaid
{level 2 diagram}
```

## Review checklist
- [ ] {the same 3 to 6 items as the HTML checklist}

---
<sub>Generated by `/show-me-mr` from {head commit short SHA}. More: `index.html` · `explainer.mp4`</sub>
````

## Rules

- Follow `ste-writing.md` for all prose.
- Use the same views, wording, and review order as the chat answer and the HTML page. Do not write three different explanations.
- Use relative links to `index.html` and `explainer.mp4` in the footer, and only for files that exist.
- Link paths to the host at the head commit when you know the URL (`{repo_url}/blob/{sha}/{path}` on GitHub, `{repo_url}/-/blob/{sha}/{path}` on GitLab). Otherwise use backticked paths.
- Keep it under ~400 lines. When a view is too large, shorten it and put the full version in the HTML page.
- For `--post`, post this file without the footer line.
